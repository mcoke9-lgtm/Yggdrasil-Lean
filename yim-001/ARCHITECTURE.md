# Cooperative AI Architecture and Core Memory System

**Architecture form:** Wave  
**Core memory form:** Particle  
**Status:** Naming and relationship adopted as the current project direction on 2026-11-10.

## The two forms

### Cooperative AI Architecture — wave form

The Cooperative AI Architecture is the single shared, logical architecture through which participating AI systems and independent tools coordinate work, exchange portable records, and continue one another's work.

**MRP-001 Working Baseline 2026-11, Revision 4** is its adopted common record contract. The identifier MRP-001 remains unchanged and continues to identify that specific adopted baseline. Calling it the Cooperative AI Architecture is the project's architectural name and wave-form association; it does not expand the normative scope of MRP-001.

There is one Cooperative AI Architecture. Required backups are redundant, recoverable copies of its authoritative materials and state, not separate competing architectures. Backup count, placement, update, and recovery rules remain to be specified and tested.

### Core Memory System — particle form

The **Core Memory System** is the particle-form realization of the memory capability within the Cooperative AI Architecture. Its current formal project identifier is **YIM-001**.

For now, the project aims for one canonical, reproducible reference Core Memory System. It must be possible to export that system and its records to other participating systems through the Cooperative AI Architecture.

An exported copy is a deployment or replica of the same identified release, not automatically a new independent system or a new architecture. Changes made independently to exports must retain their identity, version, and history so they can be reconciled rather than silently overwriting the canonical source.

## Relationship

- The wave form defines the shared rules and pathways for cooperation.
- The particle form provides the concrete, reproducible memory capability that operates within those rules.
- The architecture carries portable releases, records, evidence, and handoffs between systems.
- The Core Memory System remains reproducible and portable; it must not depend on one AI provider or one conversation.
- Backups preserve the Cooperative AI Architecture's authoritative materials and state. They do not create multiple authorities.

## Scope boundary

MRP-001 Revision 4 remains adopted and unchanged. Its minimal records profile does not itself specify networking, provenance, durable persistence, backup, or recovery. Those capabilities belong to the wider Cooperative AI Architecture and its separately specified components.

The current YIM-001 checkpoint is an in-memory reference core. It is not yet a durable, synchronized, or independently deployable memory service. Exportability of the reproducible system is a target, not a verified current capability.

## Current direction

1. Preserve one authoritative Cooperative AI Architecture and maintain verified backups.
2. Maintain one canonical, reproducible Core Memory System release.
3. Make releases and records exportable through the architecture.
4. Preserve source identity, version, provenance/evidence, and history during transfer.
5. Reconcile divergent exports explicitly; never silently discard competing work.
