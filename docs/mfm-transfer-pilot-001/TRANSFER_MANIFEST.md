## Verification rules and boundaries

- Original Library records remain unchanged.
- Each source's raw-byte SHA-256 is computed before transfer.
- GitHub read-back must be compared against the source text; the GitHub blob SHA is recorded separately.
- Airtable records preserve source identifiers, source status wording, source timestamp, source hash, GitHub path, commit, and transfer status.
- A successful transfer verifies persistence and content read-back, not the mathematical correctness or adoption of the source's claims.
- The pilot is additive. It does not establish GitHub as the permanent canonical store for every artifact, nor does it establish that the complete archive has been migrated.
- Dropbox has not been populated.
